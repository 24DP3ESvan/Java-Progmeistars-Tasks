# Library management concurrency task

Учебный проект Spring Boot + SQLite.

Архитектура уже приведена в порядок: контроллер, сервис, DTO, mapper, policy/strategy и factory разделены по ответственностям. Теперь это задание не про исправление design smells, а про поиск и исправление **concurrency issues**.

## Домен

- Есть обычные книги `HOME_LOAN`, которые можно брать домой.
- Есть книги из читального зала `READING_ROOM`, их нельзя брать домой.
- Книга может быть выдана только одному читателю.
- Пользователи могут одновременно вызывать REST API.

## Что уже есть

- SQLite
- REST controller
- JPA repository
- DTO вместо entity в API
- mapper
- Strategy/Policy для правил выдачи
- Factory для экспорта книг
- начальные данные

## Endpoint'ы

- `GET /books`
- `GET /books/{id}`
- `POST /books`
- `POST /books/{id}/borrow`
- `POST /books/{id}/extend`
- `POST /books/{id}/return`
- `POST /books/{id}/queue`
- `GET /books/{id}/queue`
- `GET /books/export?format=txt`
- `GET /books/export?format=csv`

Пример body для выдачи книги:

```json
{
  "readerName": "Alice",
  "days": 7
}
```

Пример body для продления:

```json
{
  "additionalDays": 3
}
```

Пример body для очереди:

```json
{
  "readerName": "Bob"
}
```

## Что нужно найти

В проекте специально оставлены проблемы, связанные с параллельными запросами.

Ищите места, где несколько REST-запросов одновременно могут:

- взять одну и ту же книгу;
- вернуть книгу в момент, когда другой запрос её ещё обрабатывает;
- одновременно продлить и вернуть одну и ту же книгу;
- потерять одно из продлений, если два запроса меняют срок выдачи одновременно;
- сломать или рассинхронизировать очередь ожидания из-за одновременных `join queue`/`return`;
- отправить лишние или противоречивые уведомления;
- увидеть устаревшее состояние книги.

В коде есть короткие комментарии-намёки, но они не объясняют решение полностью.
