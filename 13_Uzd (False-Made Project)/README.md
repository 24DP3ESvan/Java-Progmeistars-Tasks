# Library management design task

Учебный проект Spring Boot + SQLite. Он **специально написан неидеально**.

## Домен
- Есть обычные книги, которые можно брать домой.
- Есть книги из **читального зала**, их **нельзя брать домой**.
- Храним книги, простую информацию о читателе, факт выдачи и возврата.

## Что уже есть
- SQLite
- REST controller
- JPA repository
- начальные данные
- несколько endpoint'ов

## Важное
Проект должен работать, но в коде намеренно оставлены плохие решения.
Это **задание на рефакторинг и проектирование**.

## Что нужно сделать

### 1. Найти проблемы в проектировании
Найдите примеры нарушений:
- SOLID
- KISS
- YAGNI
- DRY
- Separation of Concerns
- Composition over Inheritance

### 2. Исправить архитектуру
Рекомендуемый результат:
- controller отвечает только за HTTP
- service отвечает за бизнес-логику
- repository отвечает за доступ к БД
- entity не отдается напрямую наружу
- валидация и правила не дублируются

### 3. Внедрить паттерны
Здесь особенно уместны:
- **Strategy** — правила выдачи книги домой
- **Factory** — экспорт книг в разные форматы

### 4. Что стоит улучшить в первую очередь
- убрать логику из controller
- убрать `new` у зависимостей внутри service
- перестать возвращать entity наружу
- убрать дублирование проверок
- заменить плохое наследование на композицию или более подходящую модель
- упростить слишком длинные методы

## Endpoint'ы
- `GET /books`
- `GET /books/{id}`
- `POST /books`
- `POST /books/{id}/borrow?readerName=Alice&days=7`
- `POST /books/{id}/return`
- `GET /books/export?format=txt`
- `GET /books/export?format=csv`

## Идея итогового результата
После рефакторинга проект должен стать похож на нормальное CRUD-приложение:
- DTO
- mapper
- стратегии выдачи
- фабрика экспортёров
- аккуратная обработка ошибок
